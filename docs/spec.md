## 0. 方針

- **Spoon とのやり取りは、公式 API の認可された呼び出し（§3）だけで行う。** 内部 API、非公式ライブラリ（旧版の `@sopia-bot/core`）、画面解析、拡張機能などから取ったトークンは使わない
- 申請（[app-purpose.md](app-purpose.md)）で説明した目的・権限・保存データ・保存期間の範囲だけで動かす。動作を変えるときは、先に申請内容との差を確認し、必要なら Spoon Developers に報告・再審査を受ける
- 運用承認の前は開発・テスト目的に限る（規約第6条第4項）。開発はモックサーバー（§9）で行い、本番と同じ DJ に手元から接続しない（同じ DJ への接続は1本だけのため、本番と切断し合う）
- 対象は推しの DJ 1名だけ。利用者は推しとユーザー（開発者）の2名で、2名だけがいる Discord サーバーから操作する
- チャット本文はメモリ上で処理し、アプリの DB・ログに残さない。ダジャレと判定した発言だけを Discord に投稿する（第三者での処理として申請済み）
- 秘密情報（Client Secret、トークン、Discord ボットのトークン、DB のパスワード、暗号化鍵）は、Git、ログ、Discord、ブラウザに出さない

## 1. 機能

| # | 機能 | 内容 |
| - | ---- | ---- |
| F1 | Spoon 連携 | Discord の `/link` で10分間・1回限りの連携用 URL を発行し、推しがそれを開いて Spoon の同意画面で許可する（§5） |
| F2 | 連携の解除 | `/unlink` で接続を切り、トークンを無効化（`/v1/oauth/revoke`）して、連携に紐づくデータと Discord のダジャレ投稿を削除する（§5.4） |
| F3 | 配信の検知と通知 | 30秒ごとに `GET /v1/live` で確認し、配信が始まったら Discord のメインチャンネルに「配信に参加」ボタン付きで通知する。終わったら通知する（§6.1） |
| F4 | 参加・退室（手動） | `/join` か「配信に参加」ボタンでイベントストリームに接続する（＝ボットが入室する）。`/leave` か「退室」ボタンで切断する。自動では参加しない（§6.2） |
| F5 | Discord からのコメント送信 | Discord のチャットチャンネルへの投稿を、`POST /v1/live/chat` でボット名で配信チャットに送る（§7.2） |
| F6 | ハートコメント | 無料ハート、または有料ハート1個が届いたら、決まった文面（§7.3）を配信チャットに送る。送信待ちのものがあるあいだのハートはまとめる |
| F7 | ハートコメントのオン・オフ | 推しの配信中のチャットコマンド（`!ハート on` / `!ハート off`）と、Discord の `/heart` で切り替える。設定は DB に保存する（§7.4） |
| F8 | ダジャレ判定・投票 | 登録したリスナーのチャットを判定し、ダジャレ候補を Discord のダジャレチャンネルに投稿して、⭕/❌ の投票で「公認」または削除にする（§8） |

### 1.1 旧 kametti から削除するもの

| 削除するもの | 理由 |
| ------------ | ---- |
| ハート集計（`/hearts`、最終集計） | 不要（2026-10-15 決定） |
| Spoon → Discord のコメント転送 | 不要（2026-10-15 決定）。チャット本文を Discord に流さない |
| 温度上昇の通知 | 不要。公式 API に該当するイベントもない |
| `/join` の配信 URL・LiveID 指定 | 公式 API では連携した DJ の配信にしか入れない |
| フォロー中の配信一覧による検知、`DJ_ID` | 公式 API にない。トークンが DJ を決める |
| `scripts/check-user.ts`、`scripts/list-followings.ts` | 内部 API。公式 API に該当するものはない |
| `sopia-core/`（`@sopia-bot/core`） | 非公式ライブラリ |
| ダジャレ投稿のプロフィール画像 | 公式 API はプロフィール画像を提供しない |
| 使っていない依存（axios、express、cors、class-validator、class-transformer、reflect-metadata）と環境変数（`ACCESS_TOKEN`、`REFRESH_TOKEN`、`DJ_ID`、`TARGET_IDS`、`CHECK_INTERVAL`、`PG*`、`DIAG_DETECT`、`ADMIN_ID`） | 使わない。ダジャレの判定対象は DB で管理する（§8.1） |

## 2. 構成

1つのプロセス（pm2 `kametti`）で、次の3つを動かす。

```text
[Discord] <-- discord.js --> [kametti]
                              - Discord ボット（スラッシュコマンド、ボタン、チャットチャンネル、投票）
                              - 配信の検知（30秒ごと）と、手動参加のイベントストリーム接続
                              - ウェブ（連携用のページとコールバック、プライバシーポリシー、healthz）
                                   |
[推しのブラウザ] -- https://kametchi.com --> (Nginx Proxy Manager) --> kametti:8790
                                   |
                              [Spoon Developers API]  https://jp-openapi.spooncast.net
                              [PostgreSQL 17]         192.168.0.109（専用のロール・DB kametti）
```

| 項目 | 内容 |
| ---- | ---- |
| 言語・実行環境 | TypeScript（strict、`exactOptionalPropertyTypes`）、Node 22、ESM、pnpm 10 |
| 主な依存 | discord.js、hono・@hono/node-server、pg、kuromoji |
| 開発 | Vitest（DB は PGlite）、Biome、tsx |
| 運用 | 専用コンテナ 192.168.0.111（Ubuntu 24.04、512MB）、pm2。手元でビルドして配置する（Lens の `deploy/` に倣う） |

## 3. 使用する公式 API（これ以外は呼ばない）

| メソッド | パス | 権限 | 用途 |
| -------- | ---- | ---- | ---- |
| POST | `/v1/oauth/token` | Client Secret（Basic 認証） | 認可コードの交換、トークンの更新 |
| POST | `/v1/oauth/revoke` | Client Secret（Basic 認証） | 連携解除時のトークン無効化 |
| GET | `/v1/live` | `live.read` | 配信中かどうかと `liveId` の確認（30秒ごと） |
| GET | `/v1/live/events` | `events.chat`、`events.like` | イベントストリーム（SSE）。手動で参加しているあいだだけ接続する |
| POST | `/v1/live/chat` | `chat.send` | ハートコメントと、Discord からのコメント |

- 要求する権限は `live.read`、`events.chat`、`events.like`、`chat.send` の4つだけ。`listeners.read`、`fans.read`、`events.presence`、`events.donation`、`dj.follow` は要求しない
- HTTP クライアントは、上の表のパスだけを許可する一覧を持ち、ほかのパスへの呼び出しは送信前にエラーにする（テストで確認する）
- 同意画面の URL は `https://developers.spooncast.net/jp/oauth/authorize`
- 同意後に許可された権限（トークンの `scope`）が4つに満たない場合は、足りない機能を止めて Discord で再連携を案内する。少なくとも `live.read` がなければ連携を受け付けない

### 3.1 呼び出し回数

| 呼び出し | 頻度 |
| -------- | ---- |
| `GET /v1/live` | 30秒に1回（1日 2,880回）。実測の1日上限 200,000 に対して十分小さい |
| `GET /v1/live/events` | 参加中に1本。切断時は §6.3 のとおり間隔を空けて再接続する |
| `POST /v1/live/chat` | 1.5秒に1回まで（§7.1） |
| `POST /v1/oauth/token` | 更新は1時間に1回程度。配信がない期間もRefresh Tokenが失効しないよう、1日1回は更新する |

## 4. 公式 API の扱い（Lens から移植）

Lens の `src/spoon/` を移植する。動作は Lens の仕様書 §4・§5 と同じ。

| ファイル | 内容 | Lens からの変更 |
| -------- | ---- | ---------------- |
| `http.ts`、`errors.ts`、`clock.ts` | Bearer 認証、公式のエラー形式、429・5xx の指数バックオフ、レート制限ヘッダー | パスの許可一覧（§3）を追加 |
| `oauth.ts` | 認可 URL、コードの交換、更新、無効化 | 要求する権限を §3 の4つにする |
| `token-manager.ts` | 失効5分前の更新、同時更新の集約、新しい Refresh Token の保存、`invalid_grant` による連携解除の検知、権限縮小の検知 | なし |
| `sse.ts` | SSE のパーサー | なし |
| `api.ts` | `getLive`、`connectEvents`、`sendChat` | `getListeners`、`follow` を削除 |
| `events.ts` | イベントの解釈 | `chat` は本文 `message` を残す（ダジャレ判定とコマンドのため。メモリ上だけで使う）。`presence`・`donation` は扱わない |

- トークンの更新では古い Refresh Token がすぐに失効するため、新しいトークンは DB に保存してから使う（Lens の仕様書 §4.3）
- 401 → 1回だけ更新して再試行 → 更新が `invalid_grant` なら連携解除とみなし、§5.4 の削除を行う

## 5. Spoon 連携（Discord の招待リンク方式）

Google ログインは使わない。連携は推し1名だけで、Discord サーバーのメンバー（推しとユーザー）が操作する。

### 5.1 流れ

```text
1. Discord で /link を実行する
   → 10分間・1回限りの連携用 URL https://kametchi.com/link/<招待トークン> を、
     実行した本人にだけ見える返信（ephemeral）で返す
2. 推しが URL を開く（GET）
   → 案内のページを表示する（DJ 本人のアカウントで同意すること、
     ボットアカウントでログインしたままなら、シークレットウィンドウで開くこと）
   → この時点では招待を使わない（Discord のリンクプレビューが GET しても消費されないようにする）
3. 推しがページの「Spoonと連携する」を押す（POST）
   → 招待を「使用済み」にし、state を作って招待とブラウザの Cookie に結びつけ、
     Spoon の同意画面へ移るページを返す（メタリフレッシュとリンク）
4. 推しが Spoon の同意画面で許可する
   → https://kametchi.com/callback?code=...&state=... に戻る
5. コールバックで state・Cookie・招待を照合し、60秒以内に code をトークンへ交換して暗号化して保存する
   → ページに「連携しました」を表示し、Discord のメインチャンネルにも通知する
```

| 項目 | 内容 |
| ---- | ---- |
| 招待トークン | 32バイトの乱数（base64url）。DB には SHA-256 のハッシュだけを保存する。10分で失効し、1回だけ使える |
| state | 32バイトの乱数。DB にはハッシュを保存し、招待と Cookie の両方に結びつける。10分で失効し、使用後に消す |
| Cookie | `__Host-kametti_link`、`HttpOnly`、`Secure`、`SameSite=Lax`、`Path=/`、10分。開発中の http では `__Host-` と `Secure` を付けない |
| POST の確認 | `Origin` が `APP_BASE_URL` と同じであること |
| CSP の `form-action` | `'self'` だけ（Spoon のサイトを許可しない） |
| ヘッダー | CSP（`default-src 'self'`、`frame-ancestors 'none'`）、`Referrer-Policy: same-origin`、`Cache-Control: no-store`（Lens と同じ。`no-referrer` は使わない） |

- 連携できるのは1件だけ。連携済みのときに `/link` で連携し直した場合は、新しいトークンで置き換える（権限を足すときなどに使う）。設定・判定対象・投稿は引き継ぐ。参加中なら接続をやり直す
- **連携したのが推しのアカウントかは API では確かめられない**（公式 API に DJ の ID がない）。連携後、推しの配信中に `/join` して、ボットが推しの配信に入ることで確かめる。招待 URL が他人に渡るのを防ぐため、期限を短くし、1回限りにし、ephemeral で表示し、連携のたびに Discord に通知する

### 5.2 ページ

| パス | 内容 |
| ---- | ---- |
| `GET /link/:token` | 連携の案内と「Spoonと連携する」ボタン。招待が無効なら「この URL は使えません。Discord で /link をやり直してください」 |
| `POST /link/:token` | 招待を使用済みにし、Spoon の同意画面へ移るページを返す。フォームの応答から直接リダイレクトすると、ブラウザが CSP の `form-action` を続くリダイレクトにも当て、同意画面から Spoon のログイン画面（`www.spooncast.net`）への移動を止めるため（2026-10-15 実機で確認） |
| `GET /callback` | トークンの交換と保存。結果を表示する。`error` が返った場合（同意しなかったなど）はその旨を表示する |
| `GET /privacy` | プライバシーポリシー（取得する情報、Discord での処理、保存期間、削除の窓口） |
| `GET /healthz` | 死活監視用。`ok` だけを返す |

上記以外のパスは 404 を返す。

### 5.3 権限

Discord サーバーの全員が、すべてのコマンド・ボタンを使える（メンバーは推しとユーザーだけ。2026-10-15 決定）。コマンドは `DISCORD_GUILD_ID` のサーバーにだけ登録し、ほかのサーバーやダイレクトメッセージからの操作は受け付けない。

### 5.4 連携の解除と削除

誤って解除しないよう、`/unlink` ではすぐに解除しない（2026-10-15 決定）。

| 項目 | 内容 |
| ---- | ---- |
| 確認メッセージ | 実行した本人にだけ見える返信（ephemeral）で、解除すると削除されるもの（設定、判定対象の人数、ダジャレの投稿の件数）と「元には戻せません」を表示する |
| ボタン | 「解除する」（赤）と「キャンセル」。「解除する」が押されたときだけ解除する |
| 有効期間 | 60秒。過ぎたら「この確認は無効です」と表示し、解除しない |
| 使える人 | `/unlink` を実行した本人だけ。同じ確認では1回しか解除しない |
| 連携していないとき | 確認を出さず「Spoon と連携していません」と返す |

「解除する」が押されたら次を行う。連携解除を検知したとき（§4 の `invalid_grant`）も、トークンの無効化以外は同じ処理を行う。

1. 参加中なら切断する
2. `POST /v1/oauth/revoke` で Refresh Token を無効化する（同じ連携の Access Token も失効する）。失敗しても続ける
3. Discord のダジャレチャンネルから、記録している投稿（§8.3）をすべて削除する
4. DB から、連携・設定・判定対象・投稿の記録を削除する
5. Discord のメインチャンネルに、解除したことを通知する（削除した件数だけを書く）

## 6. 配信の検知と参加

### 6.1 検知（F3）

- 連携しているあいだ、30秒ごとに `GET /v1/live` を呼ぶ
- 前回と違う `liveId` が返ったら「配信を検知しました」をメインチャンネルに送る（配信タイトルと「配信に参加」ボタン付き）。同じ配信では1回だけ送る。起動したときに配信中なら、それも1回通知する
- 404（`OAPI_MNGR_0301`）に変わったら「配信が終了しました」を送る
- ログは状態が変わったときだけ残す（30秒ごとには残さない）

### 6.2 参加・退室（F4）

公式 API では、イベントストリームに接続しているあいだボットが部屋にいる。接続すると、Spoon がボット名でリスナーへの告知を自動で投稿する（無効化できない）。

| 操作 | 動作 |
| ---- | ---- |
| `/join`、「配信に参加」ボタン | 配信中なら接続する。返信に「退室」ボタンを付ける。配信していない、連携していない、すでに参加中のときは、その旨を返す |
| `/leave`、「退室」ボタン | 切断して「退室しました」を返す。ボタンを消す |
| 配信が終わった（`end: LIVE_ENDED`） | 退室扱いにして Discord に知らせる。次の配信は、通知から手動で参加する |

- 参加中かどうかはメモリ上だけで持つ。プロセスを再起動したら退室した状態から始め、起動時に配信中ならメインチャンネルで知らせる（自動では参加しない）
- ボタンの連打で接続をやり直さない（参加中に `/join` が来ても接続し直さない）
- ボタンの ID には `liveId` を入れ、終わった配信のボタンが押されたら「この配信は終了しています」と返す
- 配信の終了は、検知（§6.1）と退室（`end: LIVE_ENDED`）のどちらで知っても、1回だけ知らせる
- 手動の退室は操作した人への返信で伝え、メインチャンネルには知らせない

### 6.3 接続の維持

Lens の `LiveMonitor`（仕様書 §5.5）の接続部分を、手動参加に合わせて分けて使う。

| 状況 | 対応 |
| ---- | ---- |
| `end: TOKEN_EXPIRED` | トークンを更新し、すぐに接続し直す |
| `end: RECONNECT` | すぐに接続し直す |
| 切断、45秒間ハートビートがない、500・502 | 1秒から倍々に待ち（最大5分）、接続し直す |
| 1日の上限（429 と `Retry-After`） | 指定の時間だけ待つ |
| `end: DUPLICATE_CONNECTION` | 接続し直さない。退室扱いにして、Discord で「別の場所から接続されたため退室しました」と知らせる（重複して起動していないかを調べる） |
| 403 `OAPI_MNGR_0209` | 推しがボットの入場をブロックしている。退室扱いにして Discord で知らせる |
| 404 `OAPI_MNGR_0301` | 配信が終わっている。退室扱いにする |
| 401 → 更新しても 401、`invalid_grant` | 連携解除とみなし、§5.4 を行う |

`/leave` されるまで、上の「接続し直す」場合は参加中のまま扱う。

- 接続し直すたびに `GET /v1/live` で配信を確かめる。切断中に配信が終わって次の配信が始まっていた場合は、次の配信には入らずに退室する（次の配信は通知から手動で参加する）
- 連携し直したときは、参加したまま新しいトークンで接続し直す
- 同じイベント ID（`{epochMillis}-{offset}`）は2回処理しない
- 状態が変わったときだけ記録する（切断が続いても同じ記録を繰り返さない）

## 7. チャットの送信

### 7.1 送信の待ち行列

Lens の `ChatSender`（`src/bot/chat-sender.ts`）を移植し、ハートコメントと Discord からのコメントで共有する。

| 項目 | 値・扱い |
| ---- | -------- |
| 送信の間隔 | 1.5秒以上空ける |
| 429 `OAPI_MNGR_0302`（送信過多） | 5秒待って1回だけ送り直す |
| 403 `OAPI_MNGR_0208`（凍結・チャット禁止） | 待っている分も含めて捨てる |
| 404（配信していない） | 待っている分も含めて捨てる |
| 待っている送信の上限 | 20件。超えたら古いものから捨てる |
| 参加していないとき | 送らない（接続していない状態で `chat.send` が使えるかは未確認のため、§11） |

Lens からの変更: Discord からのコメントは、送った結果（送信、失敗とその理由）を呼び出し元に返す。

### 7.2 Discord からのコメント送信（F5）

- 対象は `DISCORD_CHAT_CHANNEL_ID` のチャンネルへの、ボット以外の投稿だけ（Webhook・システムメッセージも除く）
- Discord のメンション（`<@id>`）は表示名にしてから送る。前後の空白は除く
- 投稿の本文を読むため、Discord の Message Content Intent を使う（Developer Portal でオンにする）
- 結果はリアクションで返す: 送れたら ✅、失敗したら ❌ と理由の返信、送らなかったら ⚠️ と理由の返信

| 送らない場合 | 返信 |
| ------------ | ---- |
| 参加していない | 「配信に参加していないため送れません」 |
| 本文が空・空白だけ（画像やスタンプだけの投稿を含む） | 「本文がないため送れません」 |
| 200文字を超える（絵文字など BMP 外の文字は2文字として数える） | 「200文字を超えているため送れません（N文字）」 |

### 7.3 ハートコメント（F6）

送る文面（旧 kametti と同じ。4行）:

```text
𓂃 ❥ 𓊝𓂃𓂃𓂃𓂃𓂃𓂃
　　　　　　 𓈒𓏸
　　　ｼ ｭ ﾜ ー ｯ ﾁ !!
　　　　　 .゜
```

- 送る条件: 参加中で、ハートコメントがオン、かつ `like` の `type` が `FREE`、または `type` が `PAID` で `totalAmount` が 1
- 送信待ちのハートコメントがあるあいだに届いたハートには、新しく積まない（1回にまとめる）。送り終わったら次のハートで再び送る。結果として、ハートコメントは送信の間隔（1.5秒）より短い間隔では出ない
- 30秒の待ち時間は設けない（2026-10-15 決定）
- 文面が200文字以内であることをテストで確認する

### 7.4 オン・オフ（F7）

| 操作 | 内容 |
| ---- | ---- |
| 推しのチャット | `!ハート on` / `!ハート off`（別名 `!heart`。全角の「！」、全角スペース、「オン」「オフ」も受け付ける）。**推し本人の発言（`isDj: true`）だけ**を解釈する |
| Discord | `/heart state:on`、`/heart state:off`、`/heart`（現在の設定を表示） |

- 設定は DB に保存し、両方から同じ設定を変える。初期値はオン
- `/heart` だけのときは、今の設定を実行した本人にだけ表示する。変えたときは、だれが変えたかを全員に見える返信で返す
- 退室したら、送っていないハートコメントや Discord からのコメントは捨てる
- 推しのチャットコマンドで切り替えたときは、Discord のメインチャンネルに知らせる。配信チャットには成否を投稿しない（2026-10-15 決定。自動で送るのはハートコメントだけ、という申請内容と一致する）

## 8. ダジャレ判定・投票（F8）

### 8.1 判定の対象

- 判定するのは、登録したリスナー（本人の了承を得た人だけ）のチャットだけ。推し本人の発言とボットの発言は判定しない
- 公式 API の `user.id` は、ボットと DJ の組み合わせごとに暗号化された値で、旧 kametti の数字の ID（`TARGET_IDS`）は使えない。そのため対象は Discord のコマンドで登録し、DB に `user.id` だけを保存する

| コマンド | 内容 |
| -------- | ---- |
| `/dajare-target add listener:<選ぶ> memo:<必須>` | 参加中の配信で最近チャットした人（新しい順に最大25人。推し本人は含めない）から選んで登録する。一覧はメモリ上だけに持ち、退室で消す。一覧にない ID は登録できない。`memo` は一覧表示用の名前（Discord で入力したもの、50文字まで） |
| `/dajare-target remove target:<選ぶ>` | 登録を外す |
| `/dajare-target list` | 登録している対象を、`memo` で表示する |

### 8.2 判定

旧 kametti の `Shareka` と同じ方法（テストで旧版と同じ結果になることを確かめる）:

1. kuromoji で読み（カタカナ）に変換する（読みのない語は表記のまま）
2. 句読点・記号・空白・「ッ」「ー」を消し、小書きの「ャュョァィゥェォ」を大きい文字にする
3. 2文字ずつの組（2-gram）に分け、最も多く出た組の回数を数える
4. 回数が2以上で、かつ「組の長さ × 回数 ÷ 全体の文字数」が 0.5 以下なら、ダジャレ候補とする

- kuromoji の辞書は `require.resolve` で場所を求める（旧版の `node_modules/kuromoji/dict` の決め打ちをやめる）。辞書を読み込めなかったときは判定しない（表記のままで判定しない）
- 旧版のコードを `test/dajare/fixtures/legacy-shareka.ts` にそのまま残し、代表的な文で旧版と同じ結果になることをテストで確かめる
- 辞書はメモリを多く使う（実測: 読み込み後 約270MB、読み込み中は最大 約400MB）

### 8.3 投稿と投票

- ダジャレ候補は `DISCORD_DAJARE_CHANNEL_ID` に Embed で投稿する（著者「{ニックネーム}のダジャレ候補」、タイトルに本文、状況「投票受付中」）。ボットが ⭕ と ❌ を付ける
- DB には Discord のメッセージ ID と状態（投票中・公認）、投稿時刻だけを保存する。本文・ニックネーム・`user.id` は保存しない
- 投票は、ボット以外の ⭕ または ❌ が `VOTE_THRESHOLD` 票に達したら確定する。受付は投稿から24時間
  - ⭕: Embed を「🏆 公認ダジャレ！」（金色、投稿者のニックネーム、フッター「kametti Dajare System」）に書き換え、状態を公認にする
  - ❌: 投稿を削除し、記録も消す
- 投票はリアクションのイベントと DB の記録で数える（旧版の ReactionCollector と違い、再起動しても受付を続ける）。同じ投稿へのリアクションは1件ずつ順に処理し、同時に届いても二重に確定させず、取りこぼさない
- 公認の Embed に載せるニックネームは、候補の Embed から読み取る（DB には保存しない）
- Discord で投稿が手動で削除されたら、記録も消す
- 投稿は期限を設けずに残す。連携の解除時にすべて削除する（2026-10-15 決定）。リスナー本人から要望があった場合も削除する

## 9. データ

### 9.1 テーブル

| テーブル | 内容 | 保存期間 |
| -------- | ---- | -------- |
| `spoon_connection` | 連携1件。トークン（AES-256-GCM で暗号化）、失効時刻、許可された権限、状態 | 連携解除まで |
| `link_invites` | 招待トークンのハッシュ、失効時刻、使用済みか | 10分（失効後は日次の削除で消す） |
| `oauth_states` | state のハッシュ、招待、Cookie の値のハッシュ、失効時刻 | 10分、使用後すぐに削除 |
| `settings` | ハートコメントのオン・オフ | 連携解除まで |
| `dajare_targets` | 判定対象の `user.id`、`memo`、登録日時 | 連携解除まで、または本人の要望まで |
| `dajare_posts` | Discord のチャンネル ID・メッセージ ID、状態、投稿日時 | 連携解除まで、または却下・本人の要望まで |
| `app_logs` | 動作の記録（接続、切断、エラー、送信の成否と件数）。リスナーを特定する情報・チャット本文・トークンは含めない | 30日 |

- 日次の削除ジョブで、期限を過ぎた行を削除する
- バックアップは Lens と同じく7日分だけ残す

### 9.2 保存しないもの

- チャット本文（ダジャレと判定したものは Discord に投稿するだけ）、イベントやレスポンスの原文
- リスナーのニックネーム（ダジャレの投稿に表示するだけ）、判定対象以外の `user.id`
- ハートの数などの活動の記録
